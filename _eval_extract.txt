BOARDING HOUSE MANAGEMENT SYSTEM
Technical Architectural Evaluation: Problems, Visual Fixes & System Workflows

1. Additional Charges Method (Canteen & Appliance Fees)
⚠️ THE PROBLEM: Tenants incur dynamic mid-month expenses (canteen snacks, extra fridge/aircon fees). Forcing immediate payments causes payment friction, while unrecorded fees lead to financial loss for landlords.
💡 TECHNICAL FIX: Implement a Pending Ledger Aggregation (Accrual Billing) model. Log mid-month micro-transactions into a `pending_charges` table with status 'PENDING'. A scheduled Cron Job auto-consolidates these fees into the next monthly invoice.

2. Database Schema Gap (Missing Leasing & Financial Tables)
⚠️ THE PROBLEM: The initial ERD only included Users, Rooms, Inquiries, Roles, Notifications, and Activity Logs. It lacked entities to store active tenancy, binding agreements, billing statements, or payment history.
💡 TECHNICAL FIX: Extend the database schema with `leases`, `pending_charges`, and `invoices` tables, creating proper foreign key constraints to maintain relational integrity.

3. Inquiry to Booking & Race Condition Fix (Double-Booking)
⚠️ THE PROBLEM: Inquiries were non-functional text records with no state machine transitioning rooms from Available to Rented. Simultaneous booking requests from multiple users caused race conditions and double bookings.
💡 TECHNICAL FIX: Build a stateful workflow (Inquiry -> Approved -> Lease Created -> Room Occupied) guarded by Laravel database transactions with pessimistic row locking (`lockForUpdate()`).
📐 ARCHITECTURE / VISUAL FIX DIAGRAM:Tenant A ────> [Submit Inquiry] ──> Landlord Approves ──┐                                                        ▼                                           ┌──────────────────────────┐                                           │   START TRANSACTION      │                                           │ room.lockForUpdate()     │                                           └────────────┬─────────────┘                                                        │                                          Is Room AVAILABLE?                                           /              \                                       (YES)              (NO)                                         │                  │                                         ▼                  ▼                                  • Create Lease    • Throw Error                                  • Room = OCCUPIED • Rollback                                  • COMMIT
4. UI/UX Dashboard & Mobile Search Layout Fixes
⚠️ THE PROBLEM: Mobile interfaces were cluttered with excessive filter inputs, while the Landlord dashboard presented severe information overload with unorganized metrics.
💡 TECHNICAL FIX: Introduce a responsive filter bottom-sheet for mobile tenants and structure the landlord dashboard into top-level KPI metric cards followed by tabbed navigation views.
📐 ARCHITECTURE / VISUAL FIX DIAGRAM:┌────────────────────────────────────────────────────────────────────────┐│                    REVISED LANDLORD DASHBOARD UI                       │├────────────────────────────────────────────────────────────────────────┤│ [ 📊 Occupancy: 85% ]   [ 💬 Pending: 4 ]   [ 💰 Monthly: $3,200 ] │├────────────────────────────────────────────────────────────────────────┤│  [ Room Listings ]    [ Inquiry Inbox ]    [ Billing & Invoices ]     │├────────────────────────────────────────────────────────────────────────┤│  ● Room 101 - Deluxe Bedspace    [ Status: OCCUPIED ]  [ Edit ]   ││  ● Room 102 - Single Studio      [ Status: AVAILABLE ] [ Edit ]   │└────────────────────────────────────────────────────────────────────────┘
5. Offline Network Outages at Canteen/POS
⚠️ THE PROBLEM: Network drops at the boarding house canteen completely halt charge logging if the web system strictly requires an active internet connection.
💡 TECHNICAL FIX: Adopt a Progressive Web App (PWA) architecture utilizing Service Workers and IndexedDB client storage to queue transactions offline, auto-syncing when connectivity resumes.
